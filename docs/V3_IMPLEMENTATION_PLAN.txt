Crystallineye V3 — Composition-Driven Visual Music Engine
Comprehensive Implementation Plan
Project objective
Transform Crystallineye from an audio-reactive procedural visualizer into a deterministic, composition-aware visual music system.
The current architecture behaves approximately like:
Music
  ↓
Live PCM snapshots
  ↓
DSP + approximate tempo
  ↓
Visual parameters
  ↓
Procedural shader
  ↓
Animation that reacts to music

V3 must instead behave like:
Imported Music
      ↓
Decode complete song
      ↓
Music Analysis
      ↓
Musical Timeline / Score
      ↓
Visual Composition Generator
      ↓
Visual Score
      ↓
Playback clock
      ↓
Persistent paint / ink renderer

The central product requirement is:
The visual composition must be created from the musical composition rather than being an independently animated shader that music merely modulates.

The target sensation is:
Someone is painting the song.

18. Do Not Treat Every Basic Pitch Note as Melody
A polyphonic song may produce many simultaneous note events.
The visualizer cannot create one brush stroke for every note.
That would become visual noise.
Create:
src/analysis/melody-extractor.ts

Input:
Basic Pitch note events

Output:
dominant melodic contour

Initial heuristic:
1. prefer high-confidence notes;
2. favor temporal continuity;
3. penalize very large pitch jumps;
4. favor sustained notes;
5. prefer a single dominant line at a time.
Use dynamic programming/Viterbi-style path selection if necessary.
The result should approximately answer:
Which note sequence would make the most coherent visual brush gesture?

This is an artistic abstraction, not a claim of perfect melody transcription.
19. Generate Chroma from Notes

For each analysis frame:
pitchClass = midiNote % 12

Normalize:

This gives us a harmonic representation without adding another ML model.

28. Scene Events
A scene roughly corresponds to a musical section.
type SceneEvent = {
  start: number;
  end: number;

  palette: PaletteDefinition;

  brushStyle: BrushStyle;

  backgroundFlow: number;

Do NOT make every section an abrupt visual reset.
Use transitions.
29. Downbeat → New Brush Gesture
Each downbeat should normally begin or anchor a major stroke.
Conceptually:
measure begins
     ↓
brush touches canvas
     ↓
stroke begins

The following beats influence the active stroke rather than creating unrelated global pulses.
This is a major change from V2.
30. Melody → Brush Trajectory
Use melody notes to build the path.
For each melodic phrase/bar:
time
→ horizontal progression

pitch
→ vertical direction

pitch interval
→ curve direction

note duration
→ segment length

note confidence
→ stroke certainty/opacity

Example:
G4 → A4 → C5 → B4

becomes

       ╭──C
     ╭─╯   ╲
G───A       B

Do not simply plot a piano-roll graph.
Use a smooth cubic spline or Bézier trajectory.
31. Normalize Pitch Spatially
Do not map MIDI pitch directly to absolute screen Y.
Determine:
track pitch range
or
section pitch range

using robust percentiles.
For example:
P10 note pitch
P90 note pitch

Then map this range into a comfortable drawing region.
This prevents songs in different registers from being pushed entirely to the top or bottom of the screen.
32. Pitch Class → Hue
Use pitch class primarily for hue.
Do NOT claim the mapping is universal.
Use an internally consistent visual system.
Recommended:
circle-of-fifths ordering

around the hue circle:
C → G → D → A → E → B → F# → C# → G# → D# → A# → F

Harmonically related pitch classes will therefore have neighboring visual colors.
Allow this mapping to be replaced later.
33. Harmony → Palette
The current chord/chroma state should define the supporting paint palette.
Example:
C major
C E G

produces a blend of related pitch colors.
When harmony changes:
palette slowly diffuses toward the new chord

Do not instantly repaint the screen.
34. Energy → Brush Pressure
Map RMS/dynamics to:
stroke width
pigment density
opacity
brush pressure

NOT primarily:
global brightness

Example:
quiet
→ thin dry stroke

loud
→ thick saturated stroke

37. Bass → Background Wash
Low-frequency energy should control a slower visual layer.
Use it for:

This creates visual weight without competing with the melody stroke.

39. Replace Randomness with Deterministic Seeds

42. Stop Using an Independent Animation Clock
This is extremely important.
Current V2:
time += dt × flowSpeed

This creates movement that can continue to feel independent from the music.
V3's master time must be:
audio playback position

Every visible event should be derived from:
songTime

Examples:
stroke progress =
(songTime - stroke.start) /
(stroke.end - stroke.start)

drop age =
songTime - drop.time

diffusion age =
songTime - stroke.createdAt

Pause:
songTime stops
everything stops

No hidden procedural clock should continue composing independently.
43. Persistent Stroke Rendering
Each stroke should remain visible after completion.
Do not keep every stroke forever at full opacity.
Within a section:
completed strokes persist
+
slowly diffuse/fade

At section transition:
old scene slowly dissolves

This creates something that feels painted rather than continuously regenerated.
44. Keep Persistence Section-Local
For performance, do not maintain every detailed stroke from a 6-minute track forever.
Keep detailed persistence for:
current section
+
possibly previous section

Earlier sections may be:
flattened
faded
or removed

This also gives musical sections visual identity.
45. Seek Reconstruction
Seeking must remain deterministic.
On seek to time T:
1. find section containing T;
2. clear runtime paint state;
3. load that section's VisualScore;
4. replay score events from section start → T without animation;
5. render resulting canvas;
6. resume live playback.
Because persistence is section-local, seek reconstruction remains bounded.

77. V3 Definition of Done
V3 is successful when:
✓ music is decoded at a known sample rate

✓ analysis happens before playback

✓ beat timestamps are known

✓ downbeat timestamps are known

✓ note events are available

✓ chroma/harmony is available

✓ structural boundaries are available

✓ MusicAnalysis is cached

✓ VisualScore is separate from MusicAnalysis

✓ brush strokes originate from musical phrases

✓ pitch influences brush trajectory/color

✓ dynamics influence stroke pressure

✓ beats influence strokes rather than global screen pulses

✓ downbeats initiate major gestures

✓ harmony influences palette

✓ percussive events can create ink drops

✓ sections alter visual composition

✓ strokes persist long enough to feel painted

✓ fluid shaders are supporting effects rather than autonomous animation

✓ playback time is the only master timeline

✓ seeking reconstructs the correct scene

✓ repeated playback is deterministic

✓ bottom player remains minimal and auto-hiding

✓ normal playback can be visually full-screen

✓ no cloud services are required

✓ no LLMs are required

Final Product Principle
Crystallineye should stop asking:
