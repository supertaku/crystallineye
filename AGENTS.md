# Project journal

Read `JOURNAL.md` when starting work in this repository.

Update it after every meaningful step: investigation findings, decisions, changes, validation results, blockers, and handoffs. Keep the voice conversational, casual, and in first person, using simple words. Be comprehensive enough to recover the work later; explain technical terms when first introduced.

Record what happened, the decision and its practical reason, relevant evidence or uncertainty, and the next step. Include the technical concepts, algorithms, important settings, tools and versions, useful commands, files and outputs involved. Keep failed attempts and their errors, fixes, alternatives, tradeoffs, and remaining limits. Use clear subsections or tables when an entry needs more detail; avoid a raw transcript of every command.

Maintain the technical memory sections as implementation changes, and link dated entries to the relevant details. Keep enough reproducible information to explain how to resume or repeat a check. Distinguish planned, considered, installed, attempted, implemented, and validated work. Separate checks actually run from results reported in older documentation, and desktop/emulator evidence from physical-device evidence.

Append dated entries using Asia/Manila time. Preserve earlier entries; explain changed decisions in a new entry. Start the history from what is known and never invent earlier work or results.
